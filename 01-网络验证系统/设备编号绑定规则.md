# 设备编号绑定规则

## 1. 定位

设备绑定的唯一业务口径为：

```text
账号 + 项目 + 设备编号
```

本系统处于开发期，不保留历史双轨。设备编号既是用户可理解、可操作的设备标识，也是后端、PC 中控、安卓端、前端、文档共同使用的绑定主键。

---

## 2. 核心规则

1. 安卓端登录必须填写设备编号。
2. 同一账号、同一项目下，设备编号唯一。
3. 新设备编号在授权设备数量范围内可以创建新设备绑定。
4. 同一设备编号重复登录，不创建新绑定，只复用原绑定并更新在线状态和最后心跳时间。
5. 已达到授权设备数量上限时，新设备编号登录必须拒绝。
6. PC 中控解绑某个设备编号后，该设备编号不再占用授权设备数量。
7. 解绑后的设备编号可以再次登录并重新创建绑定。
8. `connection_type / connection_label` 不参与后端设备绑定唯一性，不由安卓端登录/心跳作为绑定字段上报。
9. PC 中控设备列表中的连接类型、连接标识由 PC 中控侧通过 ADB 命令查询后生成，只作为本地连接展示信息。

---

## 3. 用户输错设备编号的处理

用户输错设备编号不被系统视为异常。

如果输错后的编号在当前账号、当前项目下不存在，并且授权设备数量未满，则它就是一个新的设备编号，允许创建新绑定。

如果输错后的编号已经存在，则不允许创建第二条绑定，只复用已有绑定。

如果授权设备数量已满，则拒绝创建新绑定，并提示设备数量已达上限。

---

## 4. 唯一约束

主库设备绑定表必须使用以下唯一约束：

```text
user_id + game_project_id + device_id
```

不再使用额外硬件序列、自动生成标识或不可见标识参与唯一性判断。

---

## 5. 登录流程

安卓端登录请求字段：

```json
{
  "username": "user001",
  "password": "******",
  "project_uuid": "00000000-0000-0000-0000-000000000001",
  "device_id": "A118",
  "client_type": "android"
}
```

后端处理顺序：

1. 校验账号密码。
2. 校验项目是否存在且启用。
3. 校验用户在该项目下是否有有效授权。
4. 若客户端为安卓端，按 `user_id + game_project_id + device_id` 查询设备绑定。
5. 如果绑定已存在，复用原绑定并更新登录上下文。
6. 如果绑定不存在，检查授权设备数量。
7. 数量未满则创建绑定。
8. 数量已满则拒绝登录。
9. 写入登录日志和刷新令牌上下文。

禁止在登录流程中使用以下字段作为设备绑定依据：

```text
connection_type
connection_label
硬件序列号
隐藏设备唯一标识
```

---

## 6. 心跳流程

安卓端心跳请求字段：

```json
{
  "device_id": "A118",
  "status": "idle",
  "game_data": {}
}
```

后端按以下口径处理：

1. 从 Access Token 获取账号与项目上下文。
2. 按 `user_id + game_project_id + device_id` 查找有效绑定。
3. 找不到绑定则拒绝心跳。
4. 找到绑定则写入 Redis 实时心跳。
5. Celery 定时把 Redis 心跳落库到对应游戏库。

禁止在心跳流程中把 `connection_type / connection_label` 当成后端绑定字段。

---

## 7. Redis 心跳 Key

实时心跳 Key 使用设备编号：

```text
device:runtime:{game_id}:{user_id}:{device_id}
```

在线集合成员使用：

```text
{user_id}:{device_id}
```

用户维度在线集合成员使用：

```text
device_id
```

---

## 8. 游戏库运行态

游戏库 `device_runtime` 表以设备编号作为主键：

```text
device_id
```

字段口径：

| 字段 | 说明 |
| --- | --- |
| `device_id` | 设备编号，主键 |
| `user_id` | 主库用户 ID |
| `status` | running / idle / error / offline |
| `last_seen` | 最后心跳时间 |
| `game_data` | 游戏运行数据 |
| `updated_at` | 落库更新时间 |

说明：

```text
connection_type / connection_label 不属于 Verify 绑定唯一性字段，也不属于安卓心跳绑定口径。
PC 中控如需展示 USB SN、TCP 地址等连接信息，应由 PC 中控侧通过 ADB 命令查询后形成本地展示数据。
```

---

## 9. 前端与 PC 中控展示

前端、PC 中控和后台只展示设备编号，不展示隐藏标识。

设备列表主列建议：

1. 设备编号。
2. 用户。
3. 项目。
4. 在线状态。
5. 最后心跳时间。
6. 操作：查看、解绑。

PC 中控可额外展示本地连接信息：

```text
连接类型：由 PC 中控侧 ADB 查询得出，例如 usb / tcp / unknown。
连接标识：由 PC 中控侧 ADB 查询得出，例如 USB 序列号或 TCP 地址。
```

该本地连接信息只用于操作展示，不参与 Verify 设备绑定唯一性。

---

## 10. 下线项

以下概念从开发期代码、接口和文档中下线：

1. 隐藏设备唯一标识。
2. 自动读取硬件序列生成的设备身份。
3. 内部不可见设备身份。
4. 任何由安卓硬件序列号自动生成的设备绑定主键。
5. 任何以隐藏标识作为设备唯一性的接口字段、数据库字段、Redis key 或 UI 展示。
6. 任何把 `connection_type / connection_label` 当成后端设备绑定依据的设计。

最终口径：设备编号就是设备绑定主体。
