# PC 中控打包与发布

> **当前定位：** 本文记录 PC 中控从开发期源码运行到正式 EXE 交付的边界、守护任务规则、热更新风险和验收红线。  
> **证据边界：** 截至 2026-05-20，PC 中控仍处于开发期。当前已实现的是源码模式下的 Python 守护启动方案，不代表 EXE 打包、EXE 自更新或 EXE 守护任务已经完成真实闭环。

---

## 1. 总结论

1. 当前开发期运行方式是 `python main.py`。
2. 当前全局设置中的“安装/更新守护任务”和“卸载守护任务”调用的是开发期 PowerShell 脚本。
3. 当前开发期守护任务通过 `pythonw.exe` 或 `python.exe` 启动 `scripts/pccontrol_watchdog.py`，再由 watchdog 启动 `main.py`。
4. 正式交付期必须把 PC 中控打包为 EXE，不能要求客户机器安装 Conda、TZYMIR 环境或源码目录。
5. 正式 EXE 交付期，Windows 计划任务不能继续指向开发期 Python 脚本，必须指向发布包内的 EXE 启动器或 Watchdog EXE。
6. 未完成真实 EXE 打包、安装、自动登录、异常重启、热更新覆盖和卸载验证前，不允许把 PC 中控标记为“可发布闭环”。

---

## 2. 开发期与交付期运行模式

| 阶段 | 启动入口 | 守护入口 | 使用场景 | 是否可给客户交付 |
|---|---|---|---|---|
| 开发期 | `python main.py` | `pythonw scripts/pccontrol_watchdog.py` | 本机开发、调试、联调 | 否 |
| 预发布期 | 本地构建的 EXE | EXE Watchdog 或启动器 | 真实 PC 测试、路径验证、杀软验证 | 否 |
| 正式交付期 | `HiveGreatSage-PCControl.exe` | `HiveGreatSage-PCControl-Watchdog.exe` 或等价启动器 | 客户 7x24 小时运行 | 是，需通过验收 |

### 开发期真实代码边界

当前代码侧涉及文件：

```text
HiveGreatSage-PCControl/main.py
HiveGreatSage-PCControl/core/app.py
HiveGreatSage-PCControl/core/auth/auth_manager.py
HiveGreatSage-PCControl/config/default.yaml
HiveGreatSage-PCControl/scripts/pccontrol_watchdog.py
HiveGreatSage-PCControl/scripts/install_watchdog_task.ps1
HiveGreatSage-PCControl/scripts/uninstall_watchdog_task.ps1
HiveGreatSage-PCControl/ui/dialogs/global_settings_dialog.py
```

当前开发期守护链路：

```text
全局设置
  ↓
install_watchdog_task.ps1
  ↓
Windows 计划任务 HiveGreatSage-PCControl-Watchdog
  ↓
pythonw.exe scripts/pccontrol_watchdog.py
  ↓
python.exe main.py
```

这条链路只适合开发期和内部联调，不是最终客户交付形态。

## 3. 全局设置中的安装与卸载守护任务

### 当前 UI 行为

全局设置 → 运行守护：

```text
1. 启动时使用已保存账号密码自动登录
2. 主程序异常退出后由守护进程自动重启
3. 重启等待秒数
4. 预演安装
5. 安装/更新守护任务
6. 卸载守护任务
```

### 当前开发期脚本行为

`预演安装`：

```text
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/install_watchdog_task.ps1 -WhatIf
```

作用：

```text
只验证计划任务注册参数，不修改系统。
```

`安装/更新守护任务`：

```text
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/install_watchdog_task.ps1
```

作用：

```text
注册 Windows 计划任务。
计划任务在当前 Windows 用户登录时启动 watchdog。
当前不会立即启动 watchdog，避免主平台已经运行时双开。
```

`卸载守护任务`：

```text
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/uninstall_watchdog_task.ps1
```

作用：

```text
删除 Windows 计划任务。
不删除保存的账号密码。
不关闭当前正在运行的 PC 中控。
```

## 4. EXE 交付期必须调整的守护方案

### 必须改变

正式 EXE 交付期，不能继续使用：

```text
D:\ProgramData\anaconda3\envs\TZYMIR\pythonw.exe
scripts/pccontrol_watchdog.py
python main.py
```

原因：

```text
1. 客户机器不应依赖开发机 Conda 环境。
2. 客户机器不应依赖源码目录。
3. 客户机器不应要求安装 Python。
4. 源码路径和中文路径在不同客户环境中不可控。
5. EXE 自更新时，源码脚本路径与发布目录结构会发生变化。
```

### 推荐交付结构

推荐发布包结构：

```text
HiveGreatSage-PCControl/
├── HiveGreatSage-PCControl.exe
├── HiveGreatSage-PCControl-Watchdog.exe
├── config/
│   ├── default.yaml
│   └── local.yaml
├── tools/
│   └── adb/
│       └── platform-tools/
├── logs/
├── cache/
└── updater/
```

推荐守护链路：

```text
全局设置
  ↓
发布期 install_watchdog_task.ps1 或内置注册逻辑
  ↓
Windows 计划任务 HiveGreatSage-PCControl-Watchdog
  ↓
HiveGreatSage-PCControl-Watchdog.exe
  ↓
HiveGreatSage-PCControl.exe
```

### Watchdog EXE 的职责

`HiveGreatSage-PCControl-Watchdog.exe` 应只负责：

```text
1. 启动主程序 EXE。
2. 等待主程序退出。
3. 主程序正常退出时，不重启。
4. 主程序异常退出时，读取 config/local.yaml 的 runtime.restart_on_crash。
5. restart_on_crash=true 时按 runtime.restart_delay_seconds 延迟重启。
6. 写入 logs/watchdog.log。
```

不应负责：

```text
1. 登录业务。
2. 设备管理业务。
3. ADB 操作。
4. 热更新决策。
5. 账号密码读取或修改。
```

## 5. 自动登录与切换账号边界

### 自动登录

自动登录只在以下条件全部满足时生效：

```text
1. 用户在登录页勾选过“记住密码”。
2. 系统凭据中可以读取保存的账号密码。
3. config/local.yaml 中 auth.auto_login_enabled=true。
4. Verify 登录接口可用。
```

### 切换账号

切换账号必须执行：

```text
1. 关闭 auth.auto_login_enabled。
2. 删除或忽略已保存凭据。
3. 返回登录页。
4. 不删除 Windows 守护计划任务。
```

原因：

```text
守护任务只负责拉起程序，不负责固定账号。
账号切换属于应用内登录态治理。
```

## 6. 热更新与 EXE 自覆盖风险

PC 中控热更新在开发模式和 EXE 模式下不能混为一谈。

开发模式：

```text
1. 解压 zip 覆盖源码目录。
2. os.execv 重启 Python 进程。
```

EXE 模式：

```text
1. 主程序 EXE 运行时文件被占用。
2. 必须使用外部 updater.bat、Updater EXE 或 Watchdog EXE 协助更新。
3. 需要等待主程序退出后再覆盖文件。
4. 覆盖完成后再启动新 EXE。
```

EXE 模式必须实测：

```text
1. 中文路径发布目录。
2. 普通用户权限。
3. Windows Defender / 常见杀软。
4. 主程序运行中覆盖失败场景。
5. 更新失败后的回滚或 last_good 目录。
6. Watchdog 正在运行时更新主程序。
7. Watchdog 自身更新时的处理策略。
```

## 7. 打包必须包含的运行资源

正式 EXE 发布包必须包含：

```text
1. 主程序 EXE。
2. Watchdog EXE 或等价启动器。
3. config/default.yaml。
4. 可写 config/local.yaml。
5. tools/adb/platform-tools/adb.exe。
6. tools/adb/platform-tools/AdbWinApi.dll。
7. tools/adb/platform-tools/AdbWinUsbApi.dll。
8. tools/adb/platform-tools/fastboot.exe。
9. UI 资源、图标、样式文件。
10. 运行日志目录 logs/。
11. 更新缓存目录 cache/ 或 updates/。
```

不得要求客户手工准备：

```text
1. Python。
2. Conda。
3. TZYMIR 环境。
4. 源码目录。
5. 手动 PowerShell 注册脚本。
```

## 8. 发布验收红线

未通过以下项目，不允许标记为“PC 中控 EXE 可发布”：

```text
1. 双击 EXE 可启动。
2. 登录后可正常进入主平台。
3. 记住密码 + 自动登录可用。
4. 全局设置可安装守护任务。
5. Windows 重启或重新登录后，Watchdog 可自动拉起 PC 中控。
6. 主程序异常崩溃后，Watchdog 可按配置延迟重启。
7. 用户主动关闭主程序时，Watchdog 不自动重启。
8. 切换账号会关闭自动登录，不破坏守护任务。
9. 卸载守护任务后，Windows 计划任务不存在。
10. ADB 工具在 EXE 发布目录下可用。
11. 设备列表能从 Verify 拉取并结合本机 ADB 状态显示。
12. 热更新检查、下载、校验可用。
13. EXE 模式更新覆盖和重启可用。
14. 更新失败不会造成不可启动半更新状态。
15. 所有结果需要真实 Windows PC 环境验证。
```
