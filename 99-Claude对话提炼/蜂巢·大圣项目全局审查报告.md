## 五、AndroidScript 代码审查结果

### 5.1 模块完整性

**✅ 已实现的模块（22个Lua文件）：**

- 脚本/game/ - 游戏层（ui_map, ui_helper, game_main, tasks/）

### 5.2 代码质量问题

**高严重度问题：**

1. **[verify.lua] 密码明文存储风险**
   - 位置：第105行
   - 问题：使用 XOR + Base64 弱加密
   - 建议：不应持久化密码，改为仅持久化 refresh_token

2. **[heartbeat.lua] Token 过期处理不完整**
   - 位置：第79-84行
   - 问题：Token 刷新失败后仅记录日志，不中断脚本
   - 建议：刷新失败后触发 ErrorHandler.handle("fatal")

3. **[comm_lan.lua] WebSocket 回调中的线程安全问题**
   - 位置：第75-89行
   - 问题：_pending_cmd 是全局变量，可能被覆盖
   - 建议：改用消息队列

**中严重度问题：**

4. **[ocr.lua] 内存泄漏风险**
   - 位置：第126-135行
   - 问题：若 ocrBitmap 抛异常，bitmap.recycle() 不会执行
   - 建议：使用 pcall 保护

5. **[kv.lua] 并发写入风险**
   - 位置：第45-54行
   - 问题：多个线程同时调用 KV.set() 会导致文件损坏
   - 建议：添加文件锁或使用原子写入

### 5.3 安全风险

**高风险：**
- 密码加密强度不足（XOR + Base64）
- API 地址可被中间人攻击（未验证 HTTPS）
- Token 存储未加密

**中风险：**
- 代理客户端包名硬编码
- 本地存储无访问控制（SD 卡可被其他 App 读取）
- WebSocket 连接未验证（ws:// 明文传输）

### 5.4 总体评分

**代码质量评分：78/100**

### 7.1 三条核心原则的贯彻情况

**原则1：一个游戏 = 一套独立中控 + 一套独立脚本**
- 评分：✅ 部分贯彻

- 评分：⚠️ 部分贯彻
